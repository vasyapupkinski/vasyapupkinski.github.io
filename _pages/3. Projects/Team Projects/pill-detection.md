# 알약 검출 AI 진단 최적화

> **"높은 mAP는 의심을 해봐야 한다"**

---

## TL;DR

| 항목 | 내용 |
|---|---|
| **프로젝트** | 사용자 촬영 사진에서 최대 4개 알약의 이름·위치 검출 |
| **나의 역할** | 팀장(PM) — EDA 설계, 베이스라인 코드, 의사 레이블링, 모델링 |
| **핵심 성과** | 데이터 무결성 감사를 통해 mAP 0.99의 허상을 규명하고, 정제된 데이터 파이프라인으로 **진짜 신뢰할 수 있는** mAP 0.98 달성 |

## 1. 프로젝트 배경 및 기술 철학

국비 AI 학원에서 알약 검출 모델의 mAP 점수를 경쟁하는 프로젝트로 시작되었습니다. 하지만 저는 단순히 점수를 올리는 '스펙 시합'보다는 **"AI의 본질은 데이터에 있다"**는 철학을 바탕으로 프로젝트에 임했습니다.

저는 팀장(PM)으로서 모든 방향성을 주도했고, AI에서 가장 중요한 것 중 하나가 데이터라고 생각했기 때문에 **EDA를 처음부터 철저하게** 수행했습니다. 이 과정에서 이미 데이터에 뭔가 이상한 점이 있다는 점을 파악했습니다.

프로젝트 중반, 테스트셋 오염 이슈가 발생했을 때 저는 기다리지 않고 즉시 **오염 데이터 폐기 및 재분할(7:1.5:1.5)**을 단행하여 팀의 리듬을 유지했습니다. 그러나 정제 후에도 mAP 0.98이 너무 쉽게 나오는 현상을 보며, 이는 모델의 실력이 아닌 '데이터의 함정'임을 팀원들에게 설득했습니다.

> *"지금 점수를 올리는 건 허상을 쫓는 것입니다. 점수 보지 말고 데이터가 왜 이런지 심층 EDA를 합시다. 우리의 목표는 과적합 경쟁이 아니라, 데이터 무결성 규명과 일반화 모델 구축입니다."*

이 결단은 프로젝트의 정체성을 **단순 객체 탐지에서 '데이터 중심적 오디팅(Data-Centric Auditing)'**으로 전환시키는 결정적 계기가 되었습니다.

## 4. Phase 1 — 데이터 통합 및 기초 프로파일링

### 4.1 파편화된 어노테이션 통합

원본 데이터는 **4,526개의 개별 JSON 파일**로 파편화되어 있었습니다. 하나의 이미지에 4개의 알약이 있으면, 4개의 JSON이 따로 존재하는 구조였습니다. 전체 데이터셋의 가시성을 확보하기 위해, `master_data` 구조를 설계하여 이미지 파일명 기준으로 1:N 관계로 통합했습니다.

```python
# 4,526개 JSON → 1,489개 이미지별 통합 구조 설계
master_data = defaultdict(lambda: {
    'image_path': '',
    'width': 0,
    'height': 0,
    'annotations': []  # 이 이미지에 속한 모든 알약의 BBox + class
})
```

### 4.2 기초 통계

| 항목 | 수치 |
|---|---|
| 총 이미지 | 1,489장 |
| 총 바운딩 박스 | 4,526개 |
| 고유 클래스(알약 종류) | 73개 |
| 이미지 해상도 | 976×1280 px (100% 균일) |
| 이미지당 알약 수 | 3~4개 (파일명 기준) |

> **[Situation] 포인트**: 모든 이미지가 동일한 배경과 고정된 알약 배치(4개 지점) 등 YOLO가 학습하기에는 너무나도 동일한 환경적 요인들이 존재하여, 모델이 본질적인 특징을 학습하는 대신 단순한 픽셀 패턴을 암기하는 **'지름길 학습(Shortcut Learning)'**에 빠지기 매우 쉬운 **통제된 온실 환경**임을 확인했습니다.

![원본 데이터 샘플: 통제된 배경(라벤더색)과 고정된 알약 배치(4개 지점) 확인](/assets/images/projects/pill-detection/pill-sample.png)
<br>

여기서 실제 이미지를 보시면 아시겠지만 실제로 배경과 약의 위치는 고정되어 있다는걸 이미 눈치채셨을 겁니다. 모든 이미지가 동일한 배경과 동일한 위치에 알약이 배치되어 있고 이외에도 조명, 카메라 각도 등 다양한 요소들이 동일합니다. 이로인해 모델은 알약의 특징을 학습하는 대신, **"색상 + 모양 = 클래스"** 라는 단순한 룩업 테이블을 만들 수 있음을 의미합니다.

## 5. Phase 2 — 구조적 편향 발견 (지름길 학습 리스크)

### 5.1 '98.6%의 법칙' — 색상·모양의 1:1 고정

전체 73개 클래스 중 **72개(98.6%)**가 단 하나의 고유한 `[모양 + 색상]` 조합만을 가지고 있었습니다.

```
예시:
  "노란색 + 원형" → A약 (100%)
  "흰색 + 장방형" → B약 (100%)
  "분홍색 + 타원형" → C약 (100%)
```

이는 모델이 알약의 미세한 형태를 학습하는 대신, **"색상 + 모양 = 클래스"** 라는 단순한 룩업 테이블을 만들 수 있음을 의미합니다.

### 5.2 인쇄 패턴 편향 — 100% 고정

73개 클래스 **전부(100%)**가 동일한 인쇄 내용(앞면 각인 + 뒷면 각인)을 가집니다.

| 클래스 | 앞면 각인 | 뒷면 각인 | 동일 비율 |
|---|---|---|---|
| 리피토정 20mg | LIP20 | 화이자 | 100% |
| 크레스토정 20mg | ZD4522 | (없음) | 100% |
| ... | ... | ... | 100% |

모델이 색상/모양뿐만 아니라 **각인 텍스트 패턴 자체를 암기**할 가능성이 매우 높습니다.

### 5.3 환경적 편향 — 비정상적 고성능의 근본 원인

이것이 가장 치명적인 발견이었습니다:

| 환경 요소 | 편향 수준 | 값 |
|---|---|---|
| 배경색 | **100%** | 연회색 단일 배경 |
| 조명 | **100%** | 주백색 단일 조명 |
| 카메라 방위각 | **100%** | 0.0도 고정 |
| 카메라 경사각 | ~100% | 70°/75°/90° 3가지만 |
| 이미지 크기 스케일 | **100%** | 200 고정 |

> **결론**: 모든 데이터가 **동일한 실험실 조건**에서 촬영되었습니다. 기존 모델들의 비정상적으로 높은 mAP는 '알약의 특징을 학습한 결과'가 아니라, **'특정 실험실의 픽셀 패턴을 암기한 결과'**였습니다.

![환경적 편향 메타데이터 검증: 모든 데이터의 배경 및 조명 고유값이 1개뿐임을 증명](/assets/images/projects/pill-detection/some-eda.png)

## 6. 디버깅 및 트러블슈팅: 지름길 학습(Shortcut Learning) 꼼수 규명

위에서 발견된 획일적인 환경 편향을 바탕으로, 초기 모델의 높은 mAP(0.99)가 **'데이터셋 환경이 정답을 맞히기에 너무 쉬운 상태'**에서 비롯된 과적합이라 확신했습니다. 당시 저는 팀원들에게 **"지금 점수를 올리는 건 의미가 없다. 점수 보지 말고 데이터가 왜 이런지 심층 EDA를 더 철저히 하자"**고 제안하며 분석의 방향을 전면 수정했습니다. 

이후 포트폴리오를 위해 과거 프로젝트의 Jupyter Notebook을 다시 검토하는 과정에서, 당시 팀원들의 코드와 해석에 숨어있던 치명적인 오류를 발견하여 최종적인 '지름길 학습'의 증거를 확보했습니다.

### 6.1 시각화 코드 오디팅을 통한 '공간적 편향(Spatial Bias)' 발견

* **기존 분석의 한계**: 프로젝트 진행 당시 팀원(박병호 님)에게 BBox 중심점 히트맵 분석을 요청했으나, 산출물에서 데이터가 좌측 하단에 알 수 없는 형태로 뭉쳐 있어 명확한 해석이 불가능했습니다.
* **디버깅 과정**: 이를 단순한 현상이 아닌 '시각화 코드 버그'로 의심하여 제가 직접 코드를 리팩토링했습니다. 분석 결과, BBox 좌표를 0~100% 스케일로 정규화해놓고 **시각화 함수(`plt.hist2d`)에 축 범위를 설정하지 않은 버그**임을 발견했습니다. 
* **올바른 재해석**: 좌표를 수학적으로 보정하여 재시각화한 결과, 알약이 무작위가 아닌 **정확히 4개의 특정 좌표(좌상, 우상, 좌하, 우하)**에만 거의 고정적으로 등장하는 심각한 위치 편향을 확증했습니다.

![BBox 중심점 2D 히트맵: 알약이 4개의 모서리 좌표에만 고정적으로 등장하는 공간적 편향 확증](/assets/images/projects/pill-detection/bbox-heatmap.png)
<br>

### 6.2 실험 방법론 오디팅을 통한 '배경 편향' 증명

* **당시 상황(기존 분석의 한계)**: 팀원이 수행한 ResNet50 기반 t-SNE 분석 결과, '실루엣 스코어 -0.41'을 근거로 "알약들의 데이터 특징이 너무 비슷하여 구분이 어렵다"는 잘못된 해석이 도출된 상태였습니다.
* **최근 재검증(디버깅 과정)**: 분석 스크립트를 전면 재검토한 결과, 알약 객체만 Crop 하지 않고 **넓은 배경이 통째로 포함된 원본 이미지를 특징 추출 모델(ResNet50)에 통과**시키는 치명적 오류를 발견했습니다.
* **올바른 재해석**: 스코어 -0.41은 알약의 유사성 때문이 아니라, 이미지의 90%를 차지하는 **'완벽하게 동일한 라벤더색 배경'에 딥러닝 모델의 시야가 압도(Dominated)**되었기 때문입니다. 이 발견은 역설적으로 본 데이터셋의 환경 자체가 실전과 동떨어진 '공장식 단일 환경'임을 증명하는 결정적 쐐기가 되었습니다.

![t-SNE 시각화 팩트체크: 라벤더색 단일 배경에 의해 압도당해 군집이 제대로 뭉치지 못한 특징 공간](/assets/images/projects/pill-detection/tsne-plot.png)
<br>

### 6.3 역설의 결론: '지름길 학습(Shortcut Learning)' 꼼수 규명

코드 디버깅을 통해 확인된 '고정된 위치'와 '완벽히 통제된 배경'이라는 온실 환경 속에서, YOLO 모델은 알약의 입체적인 본질을 학습할 필요가 없었습니다. 다음과 같은 **지름길 학습(Shortcut Learning)**으로 꼼수를 쓰고 있었을 뿐입니다:

1. **텍스트 각인(Imprint) 의존**: 복잡한 특징을 버리고, 고정된 위치에 가서 미세한 텍스트 픽셀 패턴만 읽어냈습니다.
2. **바코드가 된 절대 픽셀 면적**: 카메라 거리가 고정된 탓에, 객체의 픽셀 크기와 비율 자체가 절대 변하지 않는 고유 바코드(ID) 역할을 해버렸습니다.
3. **변하지 않는 절대 색상값(Absolute RGB)**: 조명 변화가 전무하여, 같은 성분을 가진 하얀색 약이라도 그 미세한 고유의 헥스 코드(Hex Code) 차이를 모델이 통계적으로 그냥 암기해버린 꼴입니다.

> **결론**: 기존에 열광했던 "mAP 0.99"의 성공은 환상이었습니다. 심층적인 코드 리뷰를 통해, 이 모델은 실전에서 알약을 유연하게 탐지하는 AI가 아니라 **"완벽히 통제된 배경/조명 아래에서 특정 픽셀 크기와 텍스트만 읽어내는 기계"**로 완벽하게 과적합(Overfitting)되었음을 규명해 냈습니다.

## 7. Phase 3 — 데이터 품질 감사 (오류 탐지)

편향성 증명과 더불어, 전수 조사를 통해 치명적인 데이터 누락이 발견되었습니다.

### 7.1 라벨링 누락 — 가장 치명적 결함

파일명의 알약 ID 개수와 실제 어노테이션 개수를 교차 비교한 결과:

```
✅ Clean Set:  639장 — 파일명 기준 개수 == 어노테이션 개수
❌ Error Set:  850장 — 라벨이 누락된 불완전한 데이터 (전체의 57%)
```

| 파일명 기준 알약 수 | 실제 어노테이션 수 | 오류 건수 |
|---|---|---|
| 3개 | 1개 | 36건 |
| 3개 | 2개 | 108건 |
| 4개 | 1개 | 28건 |
| 4개 | 2개 | 194건 |
| 4개 | 3개 | 484건 |

> **영향**: Error Set을 그대로 사용하면 모델이 "4개가 보여도 3개만 탐지하라"는 잘못된 학습 신호를 받게 되어, Recall이 구조적으로 훼손됩니다.

### 7.2 기타 품질 검증

| 검사 항목 | 결과 | 조치 |
|---|---|---|
| BBox 경계 이탈 | 2건 | 제거 |
| BBox 크기 이상치(IQR 기준) | 74건 → 물리적으로 큰 알약이라 정상 | 유지 |
| IoU ≥ 0.5 중첩 | < 0.1% | 양호 |
| 메타데이터 논리 모순 (방향 vs 각인) | 23건 | 이미지 학습에 영향 제한적 |

## 8. 위기 대응 — 팀장으로서의 의사결정

Phase 3에서 드러난 이 치명적인 결함들에 대해, 팀장으로서 결단을 내려야 했습니다.

### 8.1 [Task] 데이터 오염 복구 및 오디팅(Auditing) 체계 구축
전체 데이터의 **57%가 오염(누락)**되었다는 사실을 발견한 시점에서, 저는 단순히 점수를 올리는 경쟁을 멈추고 **데이터 무결성 복구와 일반화 성능 확보**를 최우선 과제(Task)로 설정했습니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 오류 데이터 전부 제거 | 깨끗한 학습 보장 | 학습 데이터가 639장으로 반감, 과적합 위험 |
| B. 의사 레이블링으로 복원 | 데이터 규모 유지 | 복원 라벨의 정확도 불확실성 |

**의사결정**: 선택지 B를 채택했습니다.

**근거**:
1. 73개 클래스를 639장으로 학습하면 클래스당 평균 8.7장으로 극심한 과적합이 불가피(사실 애초에 시작부터 1500장으로 73개 클래스를 학습하는 것 자체가 과적합의 위험이 컸다고 저는 생각했습니다.)
2. Clean Set으로 학습한 베이스라인 모델의 신뢰도가 높다면, 의사 라벨링의 품질도 보장 가능
3. Roboflow를 통한 시각적 검증으로 복원 라벨의 수동 교정이 가능

### 8.2 팀 역할 재분배

의사 레이블링 작업은 **3명(이승완, 오현민, 최준영)**이 공동 수행하여 교차 검증하고, 나머지 인력은 모델링 실험을 병행할 수 있도록 공정을 분할했습니다.

## 9. Phase 4 — 데이터 파이프라인 구축

의사결정에 따라 다음과 같이 **[Action] 의사 레이블링 (Pseudo-Labeling) 파이프라인**을 기획 및 구현했습니다. 단순히 오류 데이터를 버려 학습 데이터가 반 토막 나는 위기를 기회로 전환하여, 정상 데이터로 베이스라인 학습 후 오류 데이터의 라벨을 자율적으로 복원하는 정밀 공정을 단행했습니다.

![데이터 파이프라인 워크플로우: 정상 데이터와 프로세스를 거쳐 복원된 데이터를 하나로 결합하여 무결성을 확보함](/assets/images/projects/pill-detection/data-pipeline-final.png)
<br>

**Roboflow**를 활용하여 복원 과정의 시각적 검증과 라벨 보정을 수행했습니다.

### 최종 데이터셋 구성

| 구분 | 수량 | 비율 |
|---|---|---|
| Train | ~1,030장 | 70% |
| Validation | ~221장 | 15% |
| Test | ~221장 | 15% |
| **총합** | **1,472장** | 100% |

이렇게 무결성을 복구해도 점수는 여전히 0.98 이상이 나왔습니다. 점수는 사실 어떻게든 올릴 수 있었지만, 저희는 이미 모델이 과적합 편향의 '꼼수'를 쓰고 있다는 것을 알고 있었습니다.

## 10. 증강 엔지니어링 (편향 대응 전략)

따라서 본격적인 모델링 전, 앞서 규명된 구조적 편향(고정된 배경과 각인 암기 등)을 강제적으로 깨뜨리기 위한 **공격적 증강 전략**부터 설계했습니다:

| 편향 유형 | 대응 증강 기법 | 목적 |
|---|---|---|
| 고정 색상 의존 | **Color Jittering** | 색상만으로 판별하는 것을 방지 |
| 고정 촬영 각도 | **Geometric Transform** (강회전, 원근변환, 뒤집기) | 카메라 앵글 의존 제거 |
| 인쇄 패턴 암기 | **Blur & Noise** (가우시안 블러, 노이즈) | 각인 세부 학습 방해 |
| 동일 클래스 부재 | **Mosaic & Copy-Paste** | 동일 알약 복수 등장 모의 |
| 균일 배경/조명 | **Background Augmentation** | 실제 배경 대응력 확보 |

## 11. Phase 5 — 최종 실험 및 기술적 오디팅

통제된 편향을 부수고 데이터 다양성을 끌어올린 환경에서, **"어떤 요소가 모델의 일반화를 결정하는가"**를 규명하기 위한 전방위 교차 실험을 진행했습니다.

### 11.1 실험 설계 철학

> **[Action] 전환된 목표**: "mAP 0.99라는 허상을 파괴하고, 공격적인 증강(Augmentation) 환경에서도 **최소 파라미터**로 **최저 Validation Loss**를 기록하며 실전에 대응 가능한 강건한 모델을 발굴하자."

| 실험 축 (Axis) | 담당자 | 탐색 범위 및 기법 (Search Space) |
| :--- | :---: | :--- |
| **Optimizer** | **이승완 (PM)** | **SGD, Adam, AdamW, RMSprop** 교차 검증 및 학습 안정성 오디팅 |
| **Model Size** | 이경식 | YOLOv8n (Nano)부터 v8m (Medium)까지 파라미터별 효율성 대조 |
| **ImgSize / LR** | 오현민 | 640/1024 해상도 대조 및 최적 Learning Rate Sweep |
| **Augmentation** | 최준영 | HSV 명도(V1~V5), Mosaic 강도, Blur 등 광학적 강건성 실험 |

### 11.2 실험 매트릭스 (Experiment Matrix)

#### Stage 1: 옵티마이저 오디팅 (Optimizer Audit)
데이터셋의 특성에 최적화된 수렴 도구를 비교 분석했습니다.

| 옵티마이저 | 초기 LR | 점수 (mAP50-95) | 결과 분석 |
| :--- | :--- | :---: | :--- |
| **SGD (Momentum)** | **0.01** | **0.9909** | **최고 성능**. 고해상도 통제 환경에서 가장 정교한 가충치 업데이트 수행 |
| **AdamW** | 0.001 | 0.9769 | 가장 안정적이고 빠른 수렴. 범용적인 일반화 능력 우수 |
| **Adam** | 0.001 | 0.9780 | 안정적이지만 SGD 대비 특징 포착 정밀도가 소폭 낮음 |
| **RMSprop** | 0.001 | 0.6739 | 본 도메인 특징 공간에서 학습 불안정성 노출 |

#### Stage 2: 모델 복잡도 비교 (Architecture & Size)
데이터의 실제 난이도와 필요한 모델 용량(Capacity)의 상관관계를 실험했습니다.

| Model | Params | mAP@50-95 | Inference (ms) | 비고 |
|---|---|---|---|---|
| YOLOv8m | 25.9M | 0.982 | 12.3 | 모델 크기 대비 성능 이득 미미 |
| YOLOv8s | 11.2M | 0.981 | 8.1 | 밸런스형 |
| **YOLOv8n** | **3.2M** | **0.981** | **4.2** | **최종 선정 (최적의 효율성)** |

→ **[Result] 결론**: Nano(3.2M) 모델이 8배 큰 Medium 모델과 동일한 성능을 보인다는 것은, 현재 데이터셋이 '모델 용량'보다 **'데이터 품질(Auditing)과 증강 전략(Action)'**에 의해 최종적인 신뢰도가 결정됨을 입증한 핵심 성과입니다.

#### Stage 3: 증강 전략 고도화 (Augmentation Detail)
광학적(Optical) 강건성 확보를 위한 세부 튜닝을 진행했습니다.

*   **HSV_V (Brightness) Sweep**: 0.1에서 0.4까지 실험한 결과, 0.4 설정 시 조명 변화에 가장 강건한 mAP 유지를 확인했습니다.
*   **Mosaic Strategy**: 고정된 위치 편향을 깨기 위해 Mosaic 비율을 0.5로 설정하고, 학습 후반부 10에포크에서 비활성화하여 정교한 BBox 학습을 유도했습니다.

### 11.3 최종 성과 요약

| Metric | Score | 세부 설정 |
|---|---|---|
| **mAP@50-95** | **0.9808** | Refined Data (1,472장) |
| **Precision** | **0.9862** | Optimizer: SGD (lr=0.01) |
| **Recall** | **0.9795** | Model: YOLOv8n (Nano) |
| **Efficiency** | **4.2ms** | Latency per unit |

## 13. Lessons Learned

### 기술적 교훈

1. **"AI의 본질은 데이터에 있다"** — 저는 데이터야말로 AI의 성패를 결정하는 가장 핵심적인 요소라고 믿습니다. 이번 프로젝트에서도 초기 EDA(탐색적 데이터 분석) 단계에서 이미 데이터의 비정상적인 분포와 편향을 예리하게 포착했습니다. 데이터를 철저히 뜯어보며 얻은 인사이트는 모델링의 방향을 결정하고 지표의 함정을 피하게 해준 가장 강력한 무기가 되었습니다.

2. **"높은 mAP는 의심의 시작이다"** — 성능 지표가 데이터의 편향을 가릴 수 있음을 배웠습니다. 특히 실험실 통제 환경에서 수집된 데이터는 모델의 일반화 능력을 보장하지 않으며, 0.99라는 점수는 성취가 아닌 인위적 편향의 신호였습니다.

3. **Data-Centric AI: 오염은 입체적이다** — 57%의 라벨 누락은 빙산의 일각이었습니다. 배경 편향, 위치 편향 등 데이터 곳곳에 숨은 복합적인 오염망을 확인하며, 모델 아키텍처(Nano → Medium)보다 데이터 품질과 다양성 개선이 성능 향상에 훨씬 효과적임을 깨달았습니다.

4. **t-SNE는 디버깅 도구다** — 특징 공간 분석을 통해 모델이 "무엇을 보고 있는지"를 시각적으로 검증할 수 있었습니다. 특히 실루엣 점수 -0.49는 일반 특징의 무력함을 명확히 증명하는 결정적 도구가 되었습니다.

### 리더십 교훈

5. **준비된 논리가 만드는 신뢰** — 초기 EDA를 통해 이미 진작에 이상함을 감지하고 논리적 근거를 완벽히 준비해 두었습니다. 덕분에 "점수가 높은데 왜 분석을 새로 하냐"는 팀 내 의구심에 대해 정량적 근거로 설득할 수 있었고, 팀원들이 저를 믿고 끝까지 따라와 줄 수 있었던 동력이 되었습니다.

6. **위기를 기회로 전환하는 결단** — 57% 데이터 오염이라는 치명적인 위기를 마주했을 때, 이를 단순한 복구가 아닌 '의사 레이블링 파이프라인'이라는 데이터 엔지니어링 역량 강화의 기회로 전환했습니다. 

7. **팀워크: 믿음과 실행력** — 저의 무모해 보일 수 있는 '오디팅 턴' 제안을 믿고 묵묵히 실행해 준 팀원들에게 깊은 감사를 느꼈습니다. 리더의 확고한 논리와 팀원들의 강력한 실행력이 결합될 때 불가능해 보이던 데이터 복구도 가능하다는 것을 배웠습니다.
